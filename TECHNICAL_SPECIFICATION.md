# Техническое задание: Telegram-бот для объявлений в группах

## 1. Назначение проекта

Разработать Telegram-бота, который позволяет пользователю создавать объявления, автоматически публиковать их в выбранных Telegram-группах по расписанию и управлять объявлениями, шаблонами и списком групп.

Бот предназначен для публикации собственных объявлений пользователя. Он не должен обходить ограничения Telegram, отправлять сообщения в группы без добавления бота или использоваться для спама.

## 2. Роли

### Пользователь

Создаёт и редактирует объявления, шаблоны и группы, запускает и останавливает рассылки.

### Администратор системы

Имеет доступ к технической статистике: число пользователей, число подключённых групп, число активных объявлений, ошибки отправки.

## 3. Стартовый сценарий

При нажатии `/start` (техническая команда Telegram для первого запуска) или `/boshlash` бот:

1. Отправляет приветственное сообщение с кратким описанием возможностей:
   - создание и автопубликация объявлений;
   - выбор групп и интервала публикации;
   - хранение шаблонов;
   - остановка, изменение и удаление рассылок.
2. Показывает постоянное меню внизу чата (Reply Keyboard):
   - `E'lonlarim`;
   - `Shablonlar`;
   - `Guruhlar`.

На каждом шаге сценариев должна быть кнопка `Orqaga`, возвращающая пользователя на предыдущий логический экран без потери уже введённых данных, если это возможно.

### Язык интерфейса

Язык бота — **узбекский**. Все пользовательские тексты без исключений должны быть написаны на узбекском языке: приветствия, пункты меню, кнопки, команды, подсказки, предупреждения, сообщения об ошибках, уведомления о публикации и статистика. Внутренние технические названия, код и схема базы данных могут оставаться на английском языке.

Основной вариант локализации — узбекский на латинице (`o‘zbekcha lotin`). Тексты интерфейса следует хранить централизованно в файле локализации, например `locales/uz.json`, чтобы в дальнейшем можно было добавить другие языки.

Обязательные пользовательские надписи:

| Сценарий | Текст на узбекском |
| --- | --- |
| Статус активного объявления | `Faol` |
| Статус остановленного объявления | `To'xtatilgan` |
| Создать объявление | `E'lon yaratish` |
| Добавить группу | `Guruh qo'shish` |
| Выбор завершён | `Tayyor` |
| Да / нет | `Ha` / `Yo'q` |
| Назад | `Orqaga` |
| Пропустить необязательное поле | `O'tkazib yuborish` |
| Немедленная публикация | `Hozir yuborish` |
| Начать по расписанию | `Jadval bo'yicha boshlash` |

Любая новая надпись добавляется в `locales/uz.json` до реализации соответствующего сценария. Русские слова не допускаются в сообщениях, кнопках, командах и уведомлениях, которые видит пользователь.

Пользовательские команды: `/boshlash`, `/guruh_ulash`, `/statistika`. Команда `/start` поддерживается только как обязательная техническая точка входа Telegram и запускает тот же сценарий, что `/boshlash`.

## 4. Функциональные требования

### 4.1. Мои объявления (`E'lonlarim`)

При выборе `E'lonlarim` бот показывает список объявлений текущего пользователя.

Для каждого объявления вывести:

- короткий фрагмент текста;
- статус: `Faol` или `To'xtatilgan`;
- интервал публикации;
- количество выбранных групп;
- ближайшее время отправки (если объявление активно).

Под списком показать кнопку `E'lon yaratish`.

При выборе одного объявления показать карточку объявления и inline-кнопки:

- `To'xtatish` — приостанавливает активную рассылку; для приостановленной рассылки показывать `Ishga tushirish`;
- `Tahrirlash` — открывает изменение данных объявления;
- `O'chirish` — запрашивает подтверждение и удаляет объявление вместе с его расписанием;
- `Orqaga`.

#### Создание объявления

После нажатия `E'lon yaratish` показать варианты:

- `Shablondan tanlash`;
- `Yangi matn kiritish`;
- `Rasmli e'lon yuborish`;
- `Orqaga`.

Если выбран шаблон, бот показывает шаблоны пользователя и позволяет выбрать один из них. Текст и фотография (если она есть) выбранного шаблона становятся содержимым нового объявления.

Если выбран ввод текста, бот просит отправить текст объявления обычным сообщением. На первом этапе поддерживается текст; в дальнейшем можно расширить до фото, видео и файлов.

#### Объявление с фотографией

При создании объявления бот также должен предложить вариант `Rasmli e'lon yuborish`.

После его выбора бот показывает пользователю на узбекском языке инструкцию:

> Agar matn va rasmli e'lon yubormoqchi bo'lsangiz, boshqa chatdagi tayyor xabarni — matni va fotosi bilan birga — shu yerga yuboring.

Пользователь пересылает готовое сообщение из другого чата в бот. Бот извлекает из пересланного сообщения:

- одну фотографию в максимальном доступном качестве;
- подпись к фотографии (caption), которая является текстом объявления;
- при необходимости пользователь может затем отредактировать подпись, контакт, имя, группы и интервал по обычному сценарию.

Если пользователь отправил только фотографию без подписи, бот должен попросить прислать текст объявления отдельным сообщением. Если отправлено обычное текстовое сообщение, создаётся текстовое объявление без фотографии.

На первом этапе поддерживается **одна фотография на одно объявление**. Поддержка нескольких изображений в альбоме, видео и документов является будущим расширением.

Фотографии не нужно и не следует сохранять на сервере приложения. В базе данных достаточно сохранить полученный от Telegram `file_id` нужного размера фотографии и текст подписи. При публикации бот вызывает метод Telegram `sendPhoto` с этим `file_id`; сам файл остаётся в инфраструктуре Telegram. Это уменьшает расходы на хранение и упрощает запуск на Render.

Ограничения:

- бот должен принимать только контент, доступный ему в пересланном сообщении;
- сообщения с включённой защитой контента (`protected content`), которые Telegram не даёт переслать, использовать нельзя;
- подпись фотографии должна проверяться на допустимую для Telegram длину; если она слишком длинная, бот предлагает сократить текст либо отправляет текст отдельным сообщением после фотографии;
- перед сохранением объявления бот показывает предпросмотр: фото (если есть) и текст.

После выбора или ввода текста бот последовательно спрашивает:

1. **Контакт для связи** — номер телефона или Telegram-аккаунт (`@username` либо ссылка на профиль). Хотя бы один контакт обязателен.
2. **Имя для обращения** — необязательное поле. Пользователь может нажать `O'tkazib yuborish`.
3. **Группы для публикации** — показать список групп пользователя с возможностью множественного выбора и кнопками `Tayyor`, `Guruh qo'shish`, `Orqaga`. Необходимо выбрать хотя бы одну группу.
4. **Интервал отправки** — предложить кнопки:
   - каждые 5, 10, 15, 20 минут;
   - каждые 1, 2, 3, 5, 8 часов.
5. **Добавить в шаблоны?** — кнопки `Ha` и `Yo'q`.
6. **Время первого запуска** — кнопки `Hozir yuborish` и `Jadval bo'yicha boshlash`. В первом случае бот отправляет объявление в выбранные группы сразу после подтверждения, затем продолжает по выбранному интервалу. Во втором случае первая отправка выполняется через выбранный интервал.

При выборе `Ha` объявление сохраняется как новый шаблон. После подтверждения бот создаёт объявление со статусом `Faol`, рассчитывает первое время публикации и сообщает об успешном запуске.

Если объявление содержит фотографию, при сохранении в шаблон должны сохраняться и текст, и Telegram `file_id` фотографии. При последующем выборе такого шаблона новое объявление создаётся с той же фотографией.

#### Изменение объявления

Редактирование должно позволять изменить отдельно:

- текст;
- телефон/Telegram-аккаунт;
- имя для обращения;
- список групп;
- интервал;
- статус публикации.

После сохранения нового интервала или списка групп бот должен пересчитать следующее время отправки.

### 4.2. Шаблоны (`Shablonlar`)

При выборе `Shablonlar` показать список шаблонов пользователя (текстовых и с фотографией) и кнопку `Shablon yaratish`. Для шаблона с фотографией в списке выводить отметку `📷`.

При нажатии `Shablon yaratish` показать варианты `Matn kiritish`, `Rasmli xabar yuborish` и `Orqaga`. Для варианта с фотографией бот показывает ту же инструкцию, что и при создании фото-объявления: пользователь может переслать готовое сообщение с фотографией и текстом из другого чата либо отправить фото с подписью непосредственно боту. Бот сохраняет текст и `file_id` одной фотографии. Файл на сервер приложения не загружается.

При выборе шаблона показать его полный текст и действия:

- `Tahrirlash`;
- `O'chirish` (с подтверждением);
- `Orqaga`.

Шаблон содержит текст объявления и, при наличии, одну фотографию через Telegram `file_id`. Контакт, имя, группы и расписание не являются частью шаблона. При открытии шаблона с фотографией бот показывает изображение и его подпись; пользователь может изменить текст, заменить/удалить фотографию либо удалить шаблон.

### 4.3. Группы (`Guruhlar`)

При выборе `Guruhlar` показать список подключённых пользователем групп и кнопки:

- `Guruh qo'shish`;
- выбор группы из списка для удаления;
- `Orqaga`.

Для каждой группы отображать название, Telegram chat ID и состояние доступа бота.

#### Добавление группы

Telegram Bot API позволяет проверить статус участника через метод `getChatMember`. Перед подключением группы бот обязан проверить, что он сам находится в группе и имеет право отправлять сообщения, а пользователь, выполняющий подключение, является администратором или владельцем этой группы.

Бот не может сам добавить себя в группу. Пользователь должен:

1. добавить бота в нужную Telegram-группу;
2. выдать боту право отправлять сообщения (для каналов — право публикации);
3. отправить в группе команду `/guruh_ulash`.

После `/guruh_ulash` бот выполняет `getChatMember` для пользователя и для самого бота. При успешной проверке он отправляет в группу и пользователю подтверждение на узбекском языке, например `Guruh muvaffaqiyatli ulandi`. При ошибке бот объясняет причину: он не добавлен в группу, у него нет права писать, либо пользователь не является администратором.

Одна Telegram-группа может быть подключена несколькими пользователями. Каждая связь «пользователь—группа» хранится отдельно; объявления пользователя используют только группы, подключённые именно этим пользователем. Один пользователь также может отключить группу только из собственного списка: сама группа и подключения других пользователей не удаляются.

При удалении группы:

- запросить подтверждение;
- удалить связь этой группы с текущим пользователем;
- исключить её из всех активных и приостановленных объявлений текущего пользователя;
- если в объявлении не осталось групп, автоматически приостановить его и уведомить пользователя.

### 4.4. Автоматическая отправка

Сервис-планировщик должен регулярно находить объявления, срок отправки которых наступил, и публиковать их в назначенных группах.

В текст отправки включать:

- текст объявления;
- имя для обращения, если оно указано;
- телефон и/или Telegram-аккаунт для связи.

Требования к обработке отправки:

- публиковать только активные объявления;
- отправлять только в проверенные группы;
- фиксировать результат каждой отправки: время, группа, успех/ошибка, описание ошибки;
- после успешного либо обработанного неуспешного запуска рассчитывать следующую дату публикации;
- при ошибке доступа (бот удалён, нет прав) помечать группу как недоступную, приостанавливать отправку в неё и уведомлять владельца;
- не создавать дубликаты при повторном запуске процесса;
- использовать идемпотентную задачу/блокировку на объявление и интервал отправки.

Ошибки должны обрабатываться по типам. Владелец объявления получает уведомление на узбекском языке при отсутствии прав у бота, удалении бота из группы, превышении лимита Telegram, временной недоступности базы данных и недействительном `file_id` фотографии. Ошибки лимитов и временной недоступности повторяются по правилам retry; ошибки доступа требуют повторного подключения группы пользователем.

### 4.5. Учёт и статистика

Система должна автоматически вести учёт:

- общего числа пользователей, запустивших бота;
- числа подключённых групп;
- числа активных, приостановленных и удалённых объявлений;
- числа шаблонов;
- количества успешных и ошибочных отправок.

Для администратора реализовать команду `/statistika` с агрегированной статистикой. Доступ к ней разрешён только Telegram ID, заданным в переменной окружения `ADMIN_IDS`.

## 5. Ограничения Telegram и защита от спама

1. Бот может писать только в чаты, куда его добавили, и только при наличии соответствующих прав.
2. Telegram не публикует единый фиксированный публичный лимит для всех ботов и чатов; ограничения и антиспам-фильтры могут меняться. Поэтому отправку необходимо ограничивать на уровне приложения.
3. Базовые защитные лимиты:
   - не более одного сообщения от одного объявления в одну группу за один запуск;
   - минимальный поддерживаемый интервал — 5 минут;
   - не более 20 сообщений в минуту суммарно от бота;
   - не более 1 сообщения в минуту в один чат;
   - при ответе Telegram `429 Too Many Requests` учитывать `retry_after`, ставить задачу на паузу до указанного времени и повторять позднее;
   - при повторяющихся ошибках доступа прекращать отправку в конкретную группу до повторной проверки.
4. Лимиты должны быть вынесены в настройки/переменные окружения, чтобы их можно было изменить без переработки бизнес-логики.
5. Следует запретить отправку в группы, не принадлежащие или не подтверждённые текущим пользователем.
6. Ввести продуктовые лимиты, настраиваемые через переменные окружения: максимальное число активных объявлений на пользователя, число подключённых групп на пользователя и число отправок в сутки на пользователя. При достижении лимита бот сообщает об этом на узбекском языке и не создаёт новую задачу отправки.

## 6. Технический стек

Выбран стек, пригодный для недорогого или бесплатного развёртывания на Render:

| Компонент | Технология | Причина выбора |
| --- | --- | --- |
| Язык | Python 3.12 | Простая разработка и хорошая поддержка Telegram-библиотек |
| Telegram API | aiogram 3 | Асинхронный фреймворк для Telegram Bot API |
| Web-приложение | FastAPI + Uvicorn | Webhook, health-check и простой HTTP-интерфейс |
| База данных | PostgreSQL | Надёжное хранение расписаний и статистики; доступна на Render |
| ORM и миграции | SQLAlchemy 2 + Alembic | Типизированная работа с БД и контроль схемы |
| Планировщик | APScheduler или собственный worker с PostgreSQL-блокировками | Выполнение периодических задач без отдельного Redis |
| Развёртывание | Render Web Service | Поддерживает webhook, переменные окружения и автодеплой из Git |

Для бесплатного Render рекомендуется режим webhook, а не long polling: сервис отвечает на входящие обновления Telegram по HTTPS. Фоновый планировщик работает в том же сервисе.

### Поддержание активности Render

Чтобы бесплатный инстанс Render не переходил в спящий режим, пользователь уже использует скрипт Google Sheets (Google Apps Script), который периодически выполняет HTTP-запрос к приложению. В приложении необходимо предоставить лёгкий публичный endpoint, например `GET /health`, возвращающий статус `200 OK` и JSON `{"status":"ok"}`. Скрипт Google Sheets должен обращаться к этому endpoint с периодичностью, достаточной для поддержания активности Render. Endpoint не запускает рассылки и не раскрывает конфиденциальные данные.

Для этапа тестирования этого решения достаточно. Планировщик должен после каждого запуска сверяться с данными в PostgreSQL, чтобы корректно обработать задачи даже при кратковременном перезапуске сервиса. Перед запуском для постоянных пользователей следует перенести базу данных на тариф с резервным копированием или другой постоянный PostgreSQL: бесплатная база Render имеет срок действия 30 дней.

## 7. Модель данных

### users

- `id` — внутренний идентификатор;
- `telegram_id` — уникальный ID пользователя Telegram;
- `username`, `first_name`;
- `created_at`, `last_activity_at`.

### groups

- `id`;
- `chat_id` — уникальный Telegram chat ID;
- `title`;
- `chat_type` — group/supergroup/channel;
- `bot_can_post`;
- `is_active`;
- `created_at`, `verified_at`.

### user_groups

- `user_id`;
- `group_id`;
- `connected_at`;
- `connected_by_telegram_id` — пользователь, выполнивший `/connect` как администратор группы;
- `is_active`.

Составной уникальный ключ: `user_id`, `group_id`. Эта таблица позволяет подключать одну группу нескольким пользователям.

### templates

- `id`;
- `user_id`;
- `text`;
- `photo_file_id` (nullable) — Telegram `file_id` фотографии; файл на сервер не сохраняется;
- `created_at`, `updated_at`.

### announcements

- `id`;
- `user_id`;
- `text`;
- `photo_file_id` (nullable) — Telegram `file_id` фотографии; файл на сервер не сохраняется;
- `contact_phone` (nullable);
- `contact_telegram` (nullable);
- `contact_name` (nullable);
- `interval_minutes`;
- `status` — active/paused/deleted;
- `next_run_at`, `last_run_at`;
- `first_run_mode` — immediate/scheduled;
- `created_at`, `updated_at`.

Ограничение: хотя бы одно из полей `contact_phone` и `contact_telegram` обязательно.

### announcement_groups

- `announcement_id`;
- `group_id`.

### delivery_logs

- `id`;
- `announcement_id`;
- `group_id`;
- `scheduled_at`, `sent_at`;
- `status` — sent/failed/rate_limited/skipped;
- `telegram_message_id`;
- `error_code`, `error_message`.

Все даты и время в базе данных (`created_at`, `updated_at`, `next_run_at`, журналы отправки) хранятся в UTC с часовым поясом. Отображение времени пользователю и расчёт понятного локального времени выполняются в часовом поясе пользователя; по умолчанию — `Asia/Tashkent`.

## 8. Интеграция и конфигурация

Необходимые переменные окружения:

- `BOT_TOKEN` — токен Telegram-бота;
- `DATABASE_URL` — строка подключения PostgreSQL;
- `WEBHOOK_BASE_URL` — публичный HTTPS URL приложения;
- `WEBHOOK_SECRET` — секретный путь или токен webhook;
- `ADMIN_IDS` — список Telegram ID администраторов;
- `MAX_MESSAGES_PER_MINUTE` — глобальный лимит;
- `MAX_MESSAGES_PER_CHAT_PER_MINUTE` — лимит на чат.
- `MAX_ACTIVE_ANNOUNCEMENTS_PER_USER` — лимит активных объявлений пользователя;
- `MAX_GROUPS_PER_USER` — лимит подключённых групп пользователя;
- `MAX_DELIVERIES_PER_USER_PER_DAY` — суточный лимит отправок пользователя.

Webhook должен быть защищён секретным токеном Telegram (`secret_token`) и принимать только запросы Telegram.

## 9. Нефункциональные требования

- Интерфейс — узбекский язык на латинице; русский язык не используется в пользовательских сообщениях, кнопках и командах.
- Все действия с объявлениями, шаблонами и группами изолированы между пользователями.
- Кнопки должны защищаться от устаревших/поддельных callback-данных: перед действием проверять владельца сущности.
- Пароли и токены не хранятся в репозитории.
- Логи не должны содержать токен бота и полный номер телефона; номер в технических логах маскируется.
- База данных должна иметь регулярные резервные копии.
- При перезапуске приложения активные объявления и расписания восстанавливаются из БД.

## 10. Критерии приёмки

1. Пользователь после `/start` видит описание на узбекском языке и меню `E'lonlarim`, `Shablonlar`, `Guruhlar`.
2. Можно создать объявление как из шаблона, так и новым текстом.
3. Можно создать текстовый или фото-шаблон, передав фото с подписью или переслав готовое сообщение; при выборе шаблона подставляются и текст, и фотография.
4. Нельзя создать объявление без телефона или Telegram-контакта и без хотя бы одной подтверждённой группы.
5. Можно выбрать один из требуемых интервалов, способ первого запуска, запустить, остановить, изменить и удалить объявление.
6. При создании объявления пользователь может сохранить его текст и фотографию как шаблон.
7. Пользователь может просмотреть, изменить и удалить только собственные шаблоны.
8. Группа подключается только после проверки прав пользователя-администратора и права бота отправлять сообщения; одну группу могут подключить несколько пользователей.
9. Планировщик отправляет активное объявление в выбранные группы и записывает результат каждой попытки в журнал.
10. При достижении лимита Telegram или продуктового лимита задача корректно откладывается либо не создаётся, не теряется и не дублируется.
11. Администратор видит статистику через `/statistika`; обычный пользователь не имеет к ней доступа.
12. Все пользовательские тексты, команды и кнопки отображаются на узбекском языке (латиница).
