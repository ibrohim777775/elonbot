# Elonbot

Публикация объявлений в Telegram-группах **из аккаунтов пользователей**. Telegram Mini App нужен только для поиска и добавления групп. Объявления, шаблоны, фото, расписание, управление аккаунтом и удаление групп остаются в боте. Весь сервер — TypeScript / Node.js: Teleproto для MTProto, grammY для управляющего бота и уведомлений, PostgreSQL для данных и расписания. Интерфейс работает без отдельной сборки и без отдельного фронтенд-сервера.

## Запуск

Нужны Node.js 22–24, PostgreSQL и публичный HTTPS-адрес приложения.

```powershell
npm ci
Copy-Item .env.example .env  # только для нового окружения; существующий .env сохраните
```

Заполните `.env`:

- `BOT_TOKEN`: токен существующего бота — он обслуживает меню, принимает фото и присылает уведомления.
- `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`: данные приложения из [my.telegram.org](https://my.telegram.org).
- `SESSION_ENCRYPTION_KEY`: постоянный секрет, 32 случайных байта в base64. Генерация: `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`. Сохраните его вместе с резервной копией БД; замена ключа делает сохранённые сессии нечитаемыми.
- `DATABASE_URL`: строка PostgreSQL. Прежний префикс `postgresql+asyncpg://` тоже принимается. `DATABASE_SSL=true` включает проверяемое TLS-соединение.
- `WEBHOOK_BASE_URL`: HTTPS-адрес приложения без завершающего `/`.
- `WEBHOOK_SECRET`: случайная строка из 16–256 букв, цифр, `_` и `-`.
- `ADMIN_IDS`: Telegram ID администраторов через запятую.

Сборка для локального запуска не нужна:

- `npm run dev` — сервер через tsx с автоматическим перезапуском при изменении TypeScript и `.env`, проверкой типов и синтаксиса JavaScript в том же терминале. Сообщения не очищаются при перезапуске.
- `npm start` — запуск TypeScript без сборки и без наблюдения за изменениями.
- `npm run check` — однократная проверка типов; `npm test` — тесты непосредственно из TypeScript.
- `npm run migrate` — отдельный запуск миграций, если нужен. Сервер сам применяет новые миграции при старте.

Ошибки в терминале показывают код, время и место в исходном файле. В режиме разработки также видны путь запроса, HTTP-статус и длительность. Токены, сессии, тела запросов, коды входа и пароли в эти логи не выводятся. После изменения HTML/CSS/JS обновите Mini App; статические файлы читаются с диска без сборки. Перезапуск сервера прерывает незавершённый вход по номеру; начните его заново. Подтверждённые сессии сохраняются.

Для ошибок Teleproto лог сохраняет исходное место сбоя и показывает `operation` (например, `uploadFile` или `messages.SendMessage`), `errorType`, а для распознанных сетевых сбоев — `reason` и `causeCode`. `TELEGRAM_UNAVAILABLE` означает общий временный сбой и сам по себе не подтверждает лимит Telegram; лимиты имеют отдельные коды `FLOOD_WAIT` / `SLOWMODE_WAIT` и `seconds`. При обращении к сохранённому отключённому клиенту сервер восстанавливает соединение. Повторные отправки сохраняют прежние идентификаторы сообщения и цикла.

Для cloudflared откройте отдельный терминал:

```powershell
cloudflared tunnel --url http://127.0.0.1:8000
```

Впишите полученный HTTPS-адрес в `WEBHOOK_BASE_URL`. В терминале проекта выполните `npm run dev`, затем откройте бота → **Guruhlar** → **Guruh qo'shish**. Команда `/app` и кнопка **Guruh qo'shish** в меню тоже открывают Mini App. Кнопка Mini App и webhook настраиваются автоматически при старте. После смены адреса туннеля обновите `.env`; режим dev перезапустит сервер. Для локального входа и webhook нужен HTTPS-туннель; HTTP допускается только для localhost при `APP_ENV=development`.

Обычное открытие `/app` в браузере показывает инструкцию входа через Telegram: API принимает только подписанные Telegram данные владельца со сроком действия один час. Для проверки интерфейса без реального Telegram предусмотрен `npm run dev -- --preview`: отдельная временная база, демонстрационные группы и адрес `PREVIEW_URL` в терминале. Этот режим слушает только `127.0.0.1`, не использует рабочую БД и не отправляет сообщения.

## Как работает

1. Пользователь открывает бота → **⚙️ Sozlamalar / Настройки** → **Telegram akkaunt** → **Akkauntni ulash**.
2. По персональной ссылке из бота открывается страница входа: номер телефона, код Telegram и, если требуется, пароль 2FA. Аккаунт должен совпадать с владельцем ссылки. В Mini App для групп входа в аккаунт нет.
3. Сессия сохраняется в PostgreSQL с AES-256-GCM и привязкой шифротекста к владельцу. Коды и пароли не сохраняются. После перезапуска вход восстанавливается.
4. В боте **Guruhlar** → **Guruh qo'shish** открывает Mini App: поиск по названию, кнопка **Ulash**, отметки уже подключённых групп и обновление списка. Бот в этих группах не нужен; приложение не вступает в группы автоматически. После добавления нажмите **Botga qaytish**, затем **Botda davom etish** в сообщении бота. Черновик объявления сохраняется. Просмотр и удаление подключённых групп остаются в боте.
5. Через меню бота **E'lonlarim / Мои объявления** можно создать и редактировать объявление, отправить до четырёх фото, выбрать до 30 подключённых групп для одного объявления и интервал 5/10/15/20/60/120/180/300/480 минут. Подключать группы можно без ограничения количества; длинные списки в боте разбиты на страницы. Сохраняются немедленный или отложенный первый запуск и удаление с выбором очистки старых публикаций. **Shablonlar / Шаблоны** хранит текст, фото, контакты, группы и все настройки расписания для повторного запуска. Доступны узбекский и русский языки.
6. Планировщик проверяет БД каждые 30 секунд. Публикация, фото/альбомы и удаление новых сообщений проходят через Teleproto. FloodWait и Slow Mode откладывают отправку. Права, лимиты и задержки изолированы по пользователям. Повтор использует постоянные MTProto `random_id` и сохранённые ID частей сообщения.
7. Ответы на автоматически отправленные объявления остаются в группах: бот их не отслеживает и не пересылает в личный чат. При удалении объявления по-прежнему можно удалить его прежние публикации.
8. **Akkauntni uzish** завершает авторизацию в Telegram и удаляет локальную сессию. Объявления и выбор групп сохраняются. Для продолжения нужно снова войти и обновить список групп.

Для каждого объявления после выбора интервала бот отдельно спрашивает **с какого времени** и **до какого времени** отправлять. На каждом шаге предлагаются кнопки с часами; можно сразу написать `7` или `07:30`, либо нажать **Boshqa vaqt kiritish**. Для окончания доступно `24:00`. Есть возврат к выбору начала и **Kun-u tun (24 soat)**. Сохранён ввод полного диапазона `7-22`, `07:30-21:45` или `22:00-07:00`. Время считается по **Asia/Tashkent (UTC+5)** независимо от часового пояса сервера. Начало включается, окончание исключается: для `7-22` с 22:00 новые публикации не начинаются, следующая возможность — 07:00. Интервал повторения действует внутри выбранных часов; пропущенные ночью интервалы не накапливаются.

Изменение: **E'lonlarim → объявление → Tahrirlash → Yuborish vaqtini o'zgartirish**. Диапазон виден в подтверждении и карточке объявления. Выбор «Hozir yuborish» тоже соблюдает эти часы. Задержка Telegram, переход между группами и завершение загрузки фото проверяются перед новой публикацией; уже отправленные части сохраняются для продолжения. Настройки хранятся в БД и переживают перезапуск. Миграция `003_sending_window.sql` применяется при старте; существующие объявления остаются круглосуточными, пока владелец не задаст диапазон.

Поддерживается вход в существующий аккаунт по номеру, коду и 2FA. Если Telegram требует отдельную проверку email или CAPTCHA, страница сообщает об этом; такой дополнительный этап пока не реализован. Подключение каналов не предлагается: назначение проекта — публикации в группах от имени пользователя.

Лимит получателей одного объявления задаёт `MAX_GROUPS_PER_ANNOUNCEMENT` (по умолчанию 30). Прежняя настройка `MAX_GROUPS_PER_USER` больше не применяется. Проверка действует при выборе групп, сохранении, редактировании и запуске из шаблона. У старого объявления с большим числом получателей планировщик отправляет только в первые 30 групп по ID; изменить состав можно через редактирование групп объявления. Для старого шаблона с превышением лимита бот предлагает сократить выбор при новом запуске. Ограничения скорости и суточного количества отправок остаются отдельными настройками.

## Готовые шаблоны

При создании объявления вопрос **«Сохранить как шаблон?»** появляется после выбора групп, интервала, ежедневных часов и первого запуска. Нажмите **«Да»**, затем **«Запустить»** на экране проверки: объявление и его шаблон сохранятся вместе. При выборе **«Нет»** создаётся только объявление. Отмена не сохраняет ни объявление, ни шаблон.

Для повторного запуска выберите **Мои объявления → Создать объявление → Выбрать из шаблонов** или **Шаблоны → нужный шаблон → Создать объявление по шаблону**. Бот сразу покажет текст, фото и сохранённые настройки; остаётся нажать **«Запустить»**. Повторно выбирать группы и время не нужно, предложение сохранить ещё один шаблон не появляется. Новый запуск рассчитывается от текущего времени с учётом сохранённого интервала и разрешённых часов; даты и история прежних отправок не копируются.

В карточке **Шаблона** доступны только запуск объявления по шаблону, **«Удалить шаблон»** и **«Назад»**. Редактирование сохранённого шаблона отключено, включая старые кнопки и незавершённые изменения. Для других настроек создайте новый шаблон. Сохранение шаблона само по себе не запускает рассылку и 7 бесплатных дней. Удаление шаблона не останавливает уже созданные из него объявления. Все настройки также видны в админке.

Миграция `006_template_settings.sql` применяется автоматически при старте. У старых шаблонов сохраняются текст и фото; если в шаблоне нет настроек, при его использовании бот запросит группы и расписание для нового объявления, сохранив сам шаблон прежним. Если группа из готового шаблона отключена или потеряно право отправки, её нужно подключить заново либо создать новый шаблон с другими группами. Запуск повторно проверяет тариф, лимит объявлений, аккаунт и доступ к каждой выбранной группе.

## Выбор языка

В главном меню нажмите **⚙️ Настройки / Sozlamalar**. Здесь находятся **Telegram-аккаунт**, **Тариф** и **🌐 Язык / Til**. Раздел также открывается командой `/settings`; кнопка **Назад** возвращает в предыдущее меню. Черновик объявления при переходе в настройки сохраняется.

Чтобы сменить язык, откройте **Настройки → 🌐 Язык / Til** или отправьте `/language`, затем выберите **Русский** или **O'zbekcha**. Выбор хранится в профиле пользователя в PostgreSQL и сохраняется после перезапуска. Черновик объявления при смене языка сохраняется; старые кнопки меню продолжают работать. Переведены меню, создание и редактирование объявлений, выбор времени, тарифы, сообщения об ошибках и служебные тексты поддержки. Пользовательские объявления и ответы администратора не переводятся автоматически.

Страница добавления групп получает язык из профиля, страница входа — из ссылки бота. После смены языка закройте и заново откройте уже открытое приложение. У существующих пользователей остаётся узбекский до их выбора; у новых начальный язык определяется по Telegram: русский для `ru`, иначе узбекский. Миграция `005_user_language.sql` применяется автоматически при старте. Для демонстрации русской версии без реальных аккаунтов: `node --import tsx app/tests/preview.ts --ru`.

## Инструкция для пользователей

Кнопка **📖 Qo'llanma / 📖 Помощь** постоянно находится в главном меню бота и открывает инструкцию внутри Telegram. Команда **/help** тоже доступна в списке команд; её использование сохраняет текущий черновик. После обновления отправьте **/start**, чтобы получить новую клавиатуру и список команд.

В Mini App сверху доступны **Группы** и **Помощь**. Переход к инструкции сохраняет список, поиск и подключённые группы; возвращение не запрашивает Telegram повторно. Инструкция работает и до подключения аккаунта. Она доступна по публичному адресу **WEBHOOK_BASE_URL/help**; эту ссылку можно вставить в описание бота вместо Telegraph. Для русского языка используйте **/help?lang=ru**, для узбекского — **/help?lang=uz**.

Текст страницы читается из `docs/foydalanish-qollanmasi-uz.md` и `docs/rukovodstvo-ru.md`. Изменения видны после повторного открытия инструкции или обновления страницы; сборка не нужна. Страница не требует входа и не обращается к Telegram или данным пользователей.

## Админка, тарифы и обращения

В `.env` укажите `ADMIN_IDS=ваш_telegram_id` (несколько ID через запятую), запустите `npm run dev` и отправьте боту **/admin**. Кнопка **Открыть админку** открывает Mini App, а **Открыть в браузере** — сайт с одноразовой ссылкой. Также в самой админке внутри Telegram есть кнопка **Открыть в браузере**, использующая [Telegram WebApp.openLink](https://core.telegram.org/bots/webapps#initializing-mini-apps). Если обычная ссылка из бота открылась внутри Telegram, сначала выберите «Открыть в браузере» в меню Telegram, затем нажмите **Войти**.

Страница `/admin` работает через тот же HTTPS-туннель cloudflared и `WEBHOOK_BASE_URL`. Ссылка действует 5 минут и используется для одного входа. Вход в браузере сохраняется на 12 часов; кнопка **Выйти** завершает его. В базе хранятся только хеши токенов, сессия передаётся через HttpOnly/Secure/SameSite cookie. Доступ из `ADMIN_IDS` проверяется при каждом запросе. После смены адреса туннеля получите новую ссылку командой `/admin`. Сборка не нужна; изменения HTML/CSS/JS видны после обновления страницы.

В админке доступны обзор сервиса, поиск пользователей и фильтр тарифа, регистрация и активность, статус Telegram-аккаунта, текущий шаг в боте, объявления с фото, контактами и расписанием, группы и права, шаблоны, история отправок и ошибок, история прежних уведомлений об ответах в группах, история активаций и переписка. Новые уведомления об ответах в группах не создаются. Списки имеют страницы. Медиа загружаются через защищённый API; токен бота, коды, ключи и сессии не выдаются в интерфейс.

- **7 дней бесплатно** начинаются при подтверждении первого объявления. Открытие бота и черновика не запускает срок. Удаление объявлений не даёт новый пробный период.
- **20 000 сум за 30 дней** включает только администратор из карточки пользователя после подтверждения оплаты. Повторная активация добавляет 30 дней к оставшемуся пробному или оплаченному сроку. История содержит администратора, сумму, сроки и примечание. Автоматических списаний нет.
- Когда доступ истёк, новые объявления и отправка блокируются. Объявления, группы и аккаунт сохраняются. После активации планировщик возобновляет рассылку с учётом времени отправки и задержек Telegram. Незавершённая публикация сохраняет уже подтверждённые ID.
- Отключение платного тарифа выполняется в админке, сохраняет действующий пробный срок и не делает возврат денег.
- **⚙️ Sozlamalar → 💳 Tarif** или `/tariff` показывает пользователю срок и условия. **✉️ Admin bilan bog'lanish** или `/support` открывает переписку с админом. Можно отправить текст, фото, документ, голосовое, аудио или видео. Черновик объявления сохраняется; завершить режим можно кнопкой **Yozishni tugatish**. Ответ администратора отправляется через бот; ответить на него можно кнопкой или Telegram Reply.
- В **Обращениях** администратор читает сообщения и отвечает текстом. Непрочитанные обращения отмечены счётчиком, бот уведомляет администраторов о новых сообщениях. Повтор одного запроса не дублирует ответ. При сетевом сбое отображается неподтверждённая доставка; автоматическая повторная отправка не выполняется.

Миграция `004_admin_billing_support.sql` применяется автоматически. Пользователям с уже существующими объявлениями даётся 7 дней с момента обновления; остальным — с первого объявления. Для проверки интерфейса без рабочей БД и реальных отправок используйте `npm run dev -- --preview`, затем откройте **ADMIN_PREVIEW_URL** из терминала. Изменения в этом режиме демонстрационные и исчезают при перезапуске.

### Рассылка пользователям бота

1. Откройте **Админка → Рассылки → Создать рассылку**.
2. Выберите шаблон **Бот снова работает** или введите свой текст на русском и узбекском. Каждый пользователь получит одну версию на выбранном им языке. Для общего текста вставьте его в оба поля. Шаблон содержит просьбу нажать `/start`.
3. Выберите **Всем пользователям бота** или **Выбрать пользователей**. Поиск работает по имени, username и Telegram ID; выбор сохраняется при поиске и переходе между страницами. За один раз можно вручную выбрать до 1000 пользователей; для варианта «всем» этого ограничения нет.
4. Нажмите **Проверить перед отправкой**. Проверьте текст и точный список получателей, затем **Отправить … пользователям**. Предпросмотр сам ничего не отправляет; состав получателей фиксируется в этот момент. Предпросмотр действителен 24 часа.
5. Следите за результатом в карточке рассылки. Можно закрыть браузер или остановить оставшуюся отправку. Уже отправленные сообщения сохраняются у пользователей, начатая отправка может завершиться после остановки.

Новые тексты можно сохранять через **Сохранить текст как шаблон**; эти шаблоны используются для рассылок администратора. Сообщения отправляются от бота в личные чаты пользователей независимо от тарифа, подключённого аккаунта и расписания объявлений. Отправки объявлений в группы продолжают работать отдельно.

Очередь хранится в PostgreSQL и продолжается после перезапуска. Скорость ограничена одним сообщением в секунду; при ответе Telegram `429` очередь ждёт `retry_after` ([ограничения Bot API](https://core.telegram.org/bots/faq#my-bot-is-hitting-limits-how-do-i-avoid-this)). Блокировка бота пользователем отмечается ошибкой. Неподтверждённые отправки автоматически не повторяются, чтобы избежать дубликатов. В карточке видны итог и ошибка каждого получателя.

Миграция `007_admin_browser_broadcasts.sql` применяется автоматически при запуске. Для проверки браузерного входа и рассылок без реального Telegram: `node --import tsx app/tests/preview.ts --browser --ru`, затем откройте **ADMIN_BROWSER_URL** из терминала. Данные и отправки в этом режиме демонстрационные.

## Переход с Python

Остановите старый процесс перед запуском Node.js. Миграция `migrations/001_typescript.sql` работает с пустой базой и прежними ревизиями Alembic. Она сохраняет пользователей, группы, объявления, шаблоны, фото и журналы, добавляя таблицы аккаунтов и новые поля. Существующие группы требуют повторной проверки через вошедший аккаунт; до этого публикаций нет.

Для старых сообщений с пустым `sender_telegram_id` удаление выполняет прежний бот. Новые публикации удаляет исключительно пользовательский аккаунт. Недоступные для удаления сообщения учитываются в уведомлении пользователю.

`src/elonbot`, `alembic`, `pyproject.toml` и прежние Python-тесты оставлены как исходный код до переноса, включая существовавшие локальные изменения. Node.js их не использует. Актуальный код — `app/`, страницы — `public/`, проверки — `app/tests/`. После перехода не запускайте Python-планировщик и Alembic параллельно с новым приложением.

## Развёртывание и проверки

Подключённые группы открываются из БД. Список доступных групп кэшируется на 5 минут; кнопка «Ro'yxatni yangilash» позволяет обновить его, но не чаще раза в минуту. Пауза `FLOOD_WAIT` при загрузке групп хранится в БД и переживает перезапуск. Во время неё показывается сохранённый список, если он есть, и оставшееся время ожидания. После выхода из аккаунта кэш удаляется. Изменения прав Telegram проверяет при отправке, а отказ отключает публикации в группе для этого пользователя.

Открытие меню и работа с черновиком не ждут завершения рассылки. Фото скачиваются один раз на объявление за проход планировщика и используются для всех его групп. Изменение действующего объявления, отключение аккаунта и удаление групп по-прежнему согласуются с отправкой. При запуске автоматически применяется дополнительная миграция `002_group_cache.sql`.

`render.yaml` использует Node.js. Настройте новые секреты и один постоянно работающий экземпляр приложения: MTProto-сессии требуют постоянного соединения, а незавершённый вход хранится в памяти этого экземпляра. Данные подтверждённых сессий и расписания находятся в БД. После простоя пропущенные интервалы не догоняются массовой рассылкой.

```powershell
npm run check
npm test
```

Тесты используют изолированную PostgreSQL в PGlite и подставной Telegram API. Они не входят в реальные аккаунты и не отправляют сообщения. Проверка живого Telegram требует заполненных API-данных и входа владельца аккаунта через страницу приложения.

Документация транспорта: [Teleproto](https://docs.teleproto.dev/), [grammY](https://grammy.dev/).
