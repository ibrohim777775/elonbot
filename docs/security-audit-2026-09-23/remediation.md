## Дополнительные изменения

- `HOST=127.0.0.1` по умолчанию закрывает прямой внешний доступ к HTTP на обычном VPS; `TRUSTED_PROXY_IPS=127.0.0.1,::1` подходит для локального Caddy. Для Render в blueprint явно указан `HOST=0.0.0.0`; доверенные адреса иных прокси требуют настройки.
- Заполненная карта HTTP-ограничений больше не блокирует всех посетителей; память ограничена 10 000 записями.
- В `.env.example` больше нет готового ключа шифрования, который могли скопировать без замены. Существующий ключ в рабочем `.env` не меняется.
- На странице входа на обоих языках объяснены полномочия сессии и её отзыв через Telegram → Настройки → Устройства.
- README и инструкция VPS описывают обновление самого скрипта, новые параметры и ограничения прав службы. [Памятка](../security.md) содержит порядок проверки VPS и действий при инциденте.

## Миграция и совместимость

`010_login_security.sql` добавляет `account_login_limits`: до 10 шагов входа и до 3 попыток запроса кода за окно 10 минут на пользователя. Новые ссылки и перезапуск не сбрасывают счётчик. Строки старше суток очищаются; актуальное окно при этом не затрагивается. Лимиты публикаций не менялись.

Миграция применяется автоматически, не удаляет пользовательские данные или сессии. Проверены повторное применение миграций и переход со старой схемы. При откате файлов скрипт сохраняет добавленную таблицу; откат к старой версии возвращает прежние дефекты безопасности.

Для этого выпуска после `git push` нужно сначала обновить внешнюю копию скрипта на сервере:

```bash
cd /home/deploy/elonbot-source
git pull --ff-only
cp scripts/update-server.sh /home/deploy/update-elonbot.sh
sudo bash /home/deploy/update-elonbot.sh
```

В дальнейшем применяется обычная команда `sudo bash /home/deploy/update-elonbot.sh`, пока сам скрипт не меняется. Пользователь `elonbot` должен быть отдельным, без sudo; служба не может работать от root. Текущий `.env` сохраняется.

## Границы проверки

Проверки завершились успешно: `npm run check`, синтаксис `public/account.js`, `bash -n scripts/update-server.sh`, полный `npm test` — **98 тестов, 98 успешных, 0 ошибок и пропусков**. После окончательного уточнения запрета общего пользователя приложения и репозитория отдельно повторён Bash-тест обновления. Новых зависимостей не добавлено. Исходные результаты `npm audit` с нулём известных уязвимостей сохранены рядом с отчётом аудита.

Тесты не выполняют привилегированное обновление Linux и не обращаются к живому Telegram. Bash-модель проверяет выбор пользователя и валидацию команд подготовки, а не реальную настройку sudo/systemd на VPS. Проверка существующего сервера, правил firewall и прав резервных копий остаётся эксплуатационной задачей.

Риск полномочий MTProto-сессий остаётся свойством выбранной архитектуры: шифрование не защищает от выполнения чужого кода в процессе с ключом. Изоляция сессий в отдельный сервис и автоматическое удаление всей учётной записи не были внедрены этим исправлением. Их нельзя считать закрытыми одной проверкой тестов.

Исторические `verification.json` и `verify.ts` сохранены как доказательства исходного состояния. Текущие проверки находятся в `app/tests/security.test.ts`, `app/tests/update-script.test.ts` и существующем наборе тестов приложения.
