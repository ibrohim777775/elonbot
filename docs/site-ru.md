# Сайт Elonbot: редактирование, запуск и SEO

## Где находится сайт

- `public/site/uz/index.html` — узбекская страница, язык по умолчанию.
- `public/site/ru/index.html` — русская страница.
- `public/site/site.css` — адаптивное оформление для обеих страниц.
- `public/site/site.js` — демонстрация отправки и раскрытие условий акции.
- `public/site/favicon.svg`, `share-uz.png`, `share-ru.png` — иконка и изображения превью ссылок.
- `app/site.ts` — выдача HTML с текущими публичными условиями и адресом сайта из конфигурации.

Frontend написан на HTML/CSS/JS, без фреймворка, npm-зависимостей для интерфейса и отдельной сборки. Текст, меню языков и FAQ работают без JavaScript. Node.js остаётся существующим сервером бота: он подставляет значения `{{...}}` в HTML до ответа посетителю. Поэтому для правильных цен и ссылок страницы нужно просматривать через сервер, а не открывать файл двойным щелчком. Динамическая акция не требует запросов из браузера к API.

Адрес `/` перенаправляет на `/uz`; `/ru` — полная русская версия. Mini App находится на `/app`, подключение аккаунта — на `/account`, админка — на `/admin`.

## Локальный запуск без сборки

```bash
npm ci
npm run dev -- --preview
```

Откройте адрес `SITE_PREVIEW_URL`, выведенный в консоли. `ADMIN_PREVIEW_URL` открывает тестовую админку. Preview использует временную базу в памяти и заглушки Telegram, реальные сообщения не отправляет. После остановки его изменения пропадут.

Для обычного режима разработки с настроенным `.env` используйте `npm run dev`. После правок HTML/CSS обновите страницу; для самого сайта команда сборки не нужна. `npm run build` остаётся проверкой и компиляцией TypeScript-сервера.

## Изменение бесплатного месяца

В админке откройте **«Бесплатный месяц» → «Количество публикаций с подписью»**, задайте положительное целое число и сохраните. После сохранения оба языка сайта и новые предложения бота показывают новое число. Если выключить предложение, его карточка и условия исчезнут с сайта. Если база ещё не готова, сайт показывает обычный пробный и платный тариф, без обещания акции.

Для уже согласившихся остаются сохранённые текст и количество. Например, смена 100 на 50 не меняет обязательства прежних участников. Считаются успешные публикации в группы; альбом в одну группу — одна публикация. После окончания бесплатных 30 дней подпись остаётся до согласованного количества, в том числе при платном продлении. Сами 30 дней не продлеваются и заменяют остаток обычного пробного срока. Миграция `012_dynamic_promotion_limit.sql` выполняется при старте и сохраняет старые согласия с количеством 100.

## Тарифы и группы

Откройте **Админка → Тарифы и лимиты**. Для каждого из трёх тарифов можно менять цену за 30 дней и группы в одном объявлении. Начальные значения: 30 / 20 000 сум, 100 / 50 000 сум, 300 / 75 000 сум. Сайт на двух языках, бот и JSON-LD получают актуальные значения из базы. HTML остаётся полным без JavaScript.

Оба бесплатных варианта получают лимит базового тарифа. Изменение предложения не меняет лимит уже начатого бесплатного или оплаченного периода. Активация выбранного платного тарифа выполняется из карточки пользователя; лимит применяется сразу, оставшийся срок продлевается на 30 дней. Миграция `013_tariff_catalog.sql` применяется автоматически. Старый `MAX_GROUPS_PER_ANNOUNCEMENT` игнорируется.

Большой тариф не повышает скорость и не отменяет ограничения Telegram. Объяснение очереди, FloodWait и 300 групп: [документация](telegram-limits-ru.md).

## Настройка сервера

На сервере выполните обычное обновление проекта по README. HTML, CSS, JS и картинки обновляются вместе с каталогом `public/`. В `.env` проверьте:

```dotenv
APP_ENV=production
# Необязательно, если основной домен уже указан в WEBHOOK_BASE_URL:
PUBLIC_SITE_URL=https://your-domain.uz
PUBLIC_BOT_USERNAME=elonyuborishbot
SITE_INDEXABLE=true
```

`your-domain.uz` замените своим доменом. `PUBLIC_SITE_URL` — только HTTPS-домен, без `/uz`, параметров и паролей. Домен должен вести на этот же сервер; одно изменение переменной не настраивает DNS или прокси. Если отдельного домена нет, не добавляйте переменную: используется `WEBHOOK_BASE_URL`. Имя публичного бота должно совпадать с работающим ботом — оно используется в кнопках сайта и примере подписи. После изменения `.env` перезапустите приложение.

`SITE_INDEXABLE` по умолчанию включён только при `APP_ENV=production`. На тестовом домене задайте `SITE_INDEXABLE=false`: страницы получат `noindex`, а robots.txt запретит обход. Закрытые страницы приложения и админки всегда получают `noindex`; доступ к личным данным по-прежнему требует авторизации.

## Что сделано для поисковиков

Для каждого языка предусмотрены отдельный URL, полное содержимое HTML, свой title и description, один H1 и последовательные заголовки. Обе страницы содержат canonical и взаимные hreflang `uz`, `ru`, `x-default`. Такой способ указывать языковые версии описан в [документации Google](https://developers.google.com/search/docs/specialty/international/localized-versions).

`/sitemap.xml` перечисляет две канонические страницы; `/robots.txt` указывает sitemap на рабочем домене. Принципы составления карты сайта: [документация Google](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap). Open Graph и Twitter Card задают изображения и текст превью для каждой версии. JSON-LD описывает сайт, бренд и услугу с реальным тарифом; вымышленных отзывов и рейтингов нет.

Все ресурсы сайта локальные, без внешних шрифтов, трекеров и Telegram SDK. При загрузке браузеру не требуется скачивать фреймворк или получать основной текст через JavaScript. Иллюстрация и демонстрация не отправляют настоящие сообщения.

## После публикации

1. Откройте `/uz` и `/ru` на своём HTTPS-домене с телефона и компьютера. Проверьте язык, стоимость, условия акции и ссылку на своего бота.
2. Проверьте исходный HTML: title, description, canonical, hreflang и `og:image` должны указывать на рабочий домен. На публичных страницах не должно быть `noindex`.
3. Откройте `/robots.txt` и `/sitemap.xml`. Карта должна содержать ваш домен и две страницы. Проверьте, что прокси не перекрывает эти адреса и не добавляет `X-Robots-Tag: noindex`.
4. Подтвердите владение доменом в Google Search Console и отправьте адрес `https://ваш-домен/sitemap.xml`. Посмотрите результат проверки обоих URL и доступность страниц для Google.
5. При изменении текстов редактируйте обе HTML-страницы и их метаданные. Число для акции меняйте в админке, а не в HTML.

Техническая подготовка помогает поисковику понять страницы, но не гарантирует индексацию или место в выдаче. Результат зависит также от домена, полезности содержания, конкуренции и внешних ссылок.
